# TUI の設計

画面の仕様(キーと動作)は [spec/tui.md](../spec/tui.md)。ここは、そう作った理由と、変えるときに守ること。

## 構成

- `tui/app.rs`: 端末に依存しない状態機械(`on_key` / `on_mouse` / `on_paste`)。テストはイベントを直接流す。
- `tui/ui.rs`: 描画だけ。`TestBackend` で画面と色を検査できる。
- `tui/{preview,markdown,tree}.rs`: プレビュー。Markdown は自前描画で、色は ANSI パレットと属性だけ。
- `create.rs`: New ビューの中身。種類(`Recipe`)、入力から Enter の動作を決める `plan`、外部コマンドを使う仕事(`Job`)。外部コマンドは `services.rs` の `Forge` の裏(本物は `SystemForge`、テストは `FakeForge`)。
- `ops.rs`: アーカイブ・復元・削除。全対象を検証(直下 1 階層か・通常ディレクトリか・移動先が空か)してから実行する。操作を足すときはここに足し、`App::execute` 経由で呼ぶ(全件選択の拒否を必ず通すため)。

## 起動速度

最初のフレームは、root 直下の読み取りだけで描く(約 3ms)。それ以外は待たない。

- zoxide のスコアは別スレッドで取り、届いたら並べ替える(カーソル位置のエントリは保つ)。
- アーカイブ一覧は、最初に `Ctrl+T` を押したときに読む。
- プレビューは現在行の分だけを描画時に作り、1 件キャッシュする。同期生成なので、巨大なディレクトリでは描画が詰まり得る(ツリーは深さ 3・300 件で打ち切り)。

## レイアウト

- モードやマーク数で、タイトル行の項目の位置と、本体の開始行が動かないようにする。件数・「N marked」は固定幅で確保し、New ビューでも同じ幅の空白を置く。
- キーの説明は常時表示せず、`?` のヘルプに置く。常時表示は項目が増えて数行を占めたため。
- ヘルプの文言は Title Case の動詞句(macOS のメニューの慣例。例: `Move to Trash`、`Open in Finder`)。例外は `Enter` の `cd`(コマンド名)。切り替えは `Toggle List: Active/Archived` のように「対象: 候補」。
- 実端末テスト(`tests/cli.rs`)のマウス座標は `FIRST_LIST_ROW` に集約している。上部の行数を変えたら直す。

## キー選びの制約

端末では区別できないキーがあるので、割り当てるときに確認する。

- `Ctrl+I` は Tab(0x09)、`Ctrl+H` は端末によって Backspace(0x08)と同じ。
- `Ctrl+Enter` は多くの端末で Enter と同じ(区別できるのは kitty keyboard protocol 対応の端末だけ)。
- ヘルプが `?` なのは、ヘルプキーとして定番で、ディレクトリ名に `?` はまず入らないから。

## 隠れた一覧を操作させない

ヘルプや New ビューで一覧が見えない間は、一覧への操作(特に `Ctrl+R` / `Ctrl+A`)とマウスを捨てる(`App::on_key` の冒頭、`App::on_new_key`)。貼り付けは文字データとしてだけ扱い、制御文字を捨てる。ショートカットにはならない。

## New ビュー

- 別ウィンドウにせず、入力行をそのまま使う(ユーザーの指定)。
- Enter の前に、Enter で何が起きるかを出す。`App` がキー入力のたびに `create::plan` を計算して持つ(`NewForm::plan`)。描画側は `Context` を持たないため。
- 検索結果が出ている間は名前と種類をロックし、Esc で結果を消して戻す。文字を変えると結果が消える作りは、直感的でないとして採らなかった。古い結果を薄く残す案、打つそばから検索する案(GitHub の検索 API は 1 分 30 回までで、`gh` の起動も遅い)も検討した。
- 外部コマンドは別スレッドで、同時に 1 つだけ実行する(`App::start` → `poll_job`)。出力は捕まえ、失敗したら stderr の最終行を状態行に出す。TUI が端末を使っているので、git には入力させない: `GIT_TERMINAL_PROMPT=0`、`GIT_SSH_COMMAND` が未設定なら `ssh -o BatchMode=yes`(パスフレーズ待ちで固まらず、失敗させる)。
- Hugging Face の検索は公開 API(`https://huggingface.co/api/{models,datasets,spaces}?search=`、認証不要)を `curl` で叩く。HTTP クライアントの crate を足さないのは、この機能のためだけに依存とビルドを重くしないため。
- LFS は既定で落とさない(`GIT_LFS_SKIP_SMUDGE=1`)。モデルの重みは数十 GB になり得るため。

種類を足すとき(例: `uv init` 済みの Python プロジェクト)は、`Recipe` に variant を足し、`label`・`hint`・`RECIPES`・`plan` を埋める。外部コマンドが要るなら `Job` と `Forge` に手順を足す。Git 化と組み合わせたくなったら、`Recipe` を「土台(空 / Git)× 雛形(なし / Python …)」の 2 軸に分ける。

## Enter で cd する仕組み

プログラムは親シェルのカレントディレクトリを変えられないので、`flatdir` はパスを stdout に出すだけで、シェル関数(`src/shell.rs`、`flatdir shell` が出力)が `$(...)` で受け取って `cd` する。

- `cd` するのは引数なし(TUI)と `root --cd` のときだけ。関数が引数を見て決める。バイナリの出力に目印を付けないのは、関数を使わない人の画面に目印が出てしまうから。
- 関数が無いと、パスが表示されるだけになる(実際にユーザーが気づかないまま使っていた)。stdout が端末のとき(= 関数に受け取られていない)は、案内を stderr に出す。
- `tests/cli.rs` が、実際の zsh / bash を pty で動かして `cd` を確かめる。

## 画面崩れ対策(文字幅)

ratatui と端末で文字幅の解釈が割れると、行の残りがずれ、行末の文字が次の行の左端に出る(日本語が一覧の左端に出る不具合として起きた)。

- 原因の候補は `⚠️`(幅 1 の基底文字 + 異体字選択子 U+FE0F)のような文字。端末ごとに幅が割れる。
- 対策 1: `tui/text.rs` の `sanitize` で、U+FE0E/FE0F、ゼロ幅文字(U+200B〜200D、U+2060)、BOM を表示前に除き、タブを 4 スペースに展開する。外から来る文字列(名前・README・検索結果)はすべて通す。
- 対策 2: TUI の間だけ端末の自動折り返しを切る(`\x1b[?7l`。終了時と panic 時に戻す)。
- 実行中のスピナーは点字(U+2800 台)。曖昧幅ではないので、`◐` などと違って端末で幅が割れない。
- 罫線などの East Asian Ambiguous な記号(`│`、`▌`)は、端末が曖昧幅を全角扱いにしていると全行がずれる。必要になったら ASCII に切り替える設定を足す。
- `pyte` は幅 2 文字の扱いが実際の端末と違い、偽陽性が出るので、画面崩れの判定には使えない。

## マウス

- マウスキャプチャは TUI の間だけ有効にし、終了時と panic 時に戻す(`TerminalGuard`)。キャプチャ中は端末のテキスト選択に Shift(端末によっては Option)が要る。
- ホイールの行き先は、直近の描画で記録したペインの矩形(`App::panes`)で決める。
- crossterm は動いただけのマウスも報告するので、`on_mouse` は再描画が必要なときだけ true を返す。
- プレビューのスクロールは、折り返し後の行数で上限を掛ける(ratatui の `unstable-rendered-line-info` 機能)。
