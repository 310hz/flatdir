# 安全設計

## 経緯

旧 sh 版の高速化中、計測のために `FZF_DEFAULT_OPTS="--filter=" flatdir restore` と `remove` を実行した。`--filter=` の fzf は対話せず全件を出力するため、全アーカイブの解除と全プロジェクトの `trash` 移動が起きた(ユーザーの `rm` エイリアスが `trash` だったため復旧できた)。原因は言語ではなく設計: fzf の出力をそのまま移動・削除へ流し、確認も実行条件もなかった。

## ガード(`src/guard.rs` ほか)

1. **対話端末必須**: TUI(引数なし)は、stdin・stderr が端末でなければ起動前に拒否。旧版の `remove` / `archive` / `restore` は TUI に統合され、TUI の外には破壊的コマンドが無い。環境変数では回避できない(テストは `Context.interactive` に値を注入する)。
2. **全件選択の拒否**: リストが 2 件以上で全てがマークされたら拒否(`App::execute` が `ops` の前に必ず通す)。通常の操作では起きない状況だけを止めるので、毎回の確認は不要。
3. **環境変数に影響されない**: 選択 UI は自前の TUI だけで、`FZF_DEFAULT_OPTS` も `SKIM_DEFAULT_OPTIONS` も読まない(`clone -s` 用に組み込んでいた skim は、clone の TUI 統合で外した)。旧版の事故原因だった「環境変数経由の `--filter`」が構造的に効かない。外部コマンドとして fzf を呼ぶ設計に戻すなら、この項目を再設計する。
4. **選択結果の検証**: TUI の対象は内部のエントリそのもの。検索結果から clone するときも、表示中の結果そのもの(`owner/name`)を使い、文字列を解釈し直さない。
5. **2 段階実行**(`ops.rs`): 全対象を検証(直下 1 階層か・通常ディレクトリか・移動先が空か)してから実行し、途中失敗で半端な状態を残さない。
6. **削除は OS のゴミ箱のみ**: `trash` crate で移動し、`rm` にフォールバックしない(macOS は `NSFileManager` 方式。Finder の「元に戻す」が出ない場合がある)。作成・clone の名前は root 直下 1 階層に限る(`..` や `/` を拒否)。

7. **削除は 1 キー(Ctrl+R)**: ユーザーの指定で、確認もモード切替も無い。安全網は、ゴミ箱経由(`rm` を使わない)、全件選択の拒否、`ops` の事前検証のみ。削除を既定の動作にしたり、確認を省いたまま対象を広げたりしない。
8. **貼り付けで発火しない**: bracketed paste の中身は文字データだけで、ショートカットにならない。
9. **作成は上書きしない**(`create.rs`): 作成・clone の行き先が root にもアーカイブにも存在しないことを確かめてから実行する。旧 `clone` サブコマンドの「確認してゴミ箱へ送って上書き」は、TUI への統合時にユーザーの判断で廃止した。
10. **New ビューから一覧の操作は届かない**: 一覧が隠れている間は、Ctrl+R / Ctrl+A / Ctrl+O などを無視する(`App::on_new_key`)。マウスも無視する。

## テスト方針

実 HOME・実 trash に触れない。`tests/commands.rs`(操作層)と `tests/tui.rs`(状態機械・描画)は使い捨てディレクトリと偽の trasher/scores。`tests/cli.rs` は `env_clear` した実バイナリを使い捨ての `HOME` で動かし、TUI を pty で操作する(ゴミ箱への Remove は実 trash に届くので対象外)。事故の再現(非対話 + `--filter=`)は `incident_regression_*` で固定している。
