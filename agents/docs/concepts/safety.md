# 安全設計

## 経緯

旧 sh 版の高速化中、計測のために `FZF_DEFAULT_OPTS="--filter=" flatdir restore` と `remove` を実行した。`--filter=` の fzf は対話せず全件を出力するため、全アーカイブの解除と全プロジェクトの `trash` 移動が起きた(ユーザーの `rm` エイリアスが `trash` だったため復旧できた)。原因は言語ではなく設計: fzf の出力をそのまま移動・削除へ流し、確認も実行条件もなかった。

## ガード(`src/guard.rs` ほか)

1. **対話端末必須**: TUI(引数なし)、`clone -s`、`clone` の上書きは、stdin・stderr が端末でなければ起動前に拒否。旧版の `remove` / `archive` / `restore` は TUI に統合され、TUI の外には破壊的コマンドが無い。環境変数では回避できない(テストは `Context.interactive` に値を注入する)。
2. **全件選択の拒否**: リストが 2 件以上で全てがマークされたら拒否(`App::execute` が `ops` の前に必ず通す)。通常の操作では起きない状況だけを止めるので、毎回の確認は不要。
3. **環境変数に影響されない**: TUI は自前、`clone -s` のピッカーは skim をライブラリとして組み込んでおり、`FZF_DEFAULT_OPTS` も `SKIM_DEFAULT_OPTIONS` も読まない(skim 側で読むのは CLI 機能の有効時のみで、この crate では無効)。旧版の事故原因だった「環境変数経由の `--filter`」が構造的に効かない。外部コマンドとして fzf を呼ぶ設計に戻すなら、この項目を再設計する。
4. **選択結果の検証**: TUI の対象は内部のエントリそのもの。`clone -s` のピッカーが返した行は、提示した行と完全一致するものだけを受け付ける。
5. **2 段階実行**(`ops.rs`): 全対象を検証(直下 1 階層か・通常ディレクトリか・移動先が空か)してから実行し、途中失敗で半端な状態を残さない。
6. **削除は OS のゴミ箱のみ**: `trash` crate で移動し、`rm` にフォールバックしない(macOS は `NSFileManager` 方式。Finder の「元に戻す」が出ない場合がある)。`init`・`clone` の名前は root 直下 1 階層に限る(`..` や `/` を拒否)。

7. **削除は 1 キー(Ctrl+R)**: ユーザーの指定で、確認もモード切替も無い。安全網は、ゴミ箱経由(`rm` を使わない)、全件選択の拒否、`ops` の事前検証のみ。削除を既定の動作にしたり、確認を省いたまま対象を広げたりしない。
8. **貼り付けで発火しない**: bracketed paste の中身は文字データだけで、ショートカットにならない。

## テスト方針

実 HOME・実 trash に触れない。`tests/commands.rs`(操作層)と `tests/tui.rs`(状態機械・描画)は使い捨てディレクトリと偽の trasher/scores。`tests/cli.rs` は `env_clear` した実バイナリを使い捨ての `HOME` で動かし、TUI を pty で操作する(ゴミ箱への Remove は実 trash に届くので対象外)。事故の再現(非対話 + `--filter=`)は `incident_regression_*` で固定している。
